# Bug fixes applied 2026-05-24

Applied findings from automated code review of mosaic3d and supporting code.
All changes compile clean with no warnings.

---

## makeVhMosaic.c

**Problem:** `vr` is declared `private` in `#pragma omp parallel private(...)` so each thread
gets an uninitialised copy. Line 255 reads `fabs(vr)` before `vr` is computed on line 261.
Undefined behaviour on the first valid pixel each thread processes.

**Fix:** Added `vr = 0.0;` inside the OMP parallel block, immediately after the per-thread
`myImg` pointer is set (before the i-loop). First pixel in each row now conservatively
treats velocity as small, zeroing slope correction — the safest default.

**To revert:** Remove the `vr = 0.0;` line.

## speckleTrackMosaic.c

**Problem:** Two VZINC incidence-angle writes (`vzTmp[i][j] = psi * RTOD`) appeared
*outside* the `if (zSp > MINELEVATION && zSp < 9999.)` block (lines 361–364 and 368–371).
`psi` is OMP-private and was only assigned inside that block, so for invalid-elevation
pixels `psi` was either uninitialised (first pixel in row) or stale from a previous j-pixel.

**Fix:** Removed both external VZINC writes. Added one VZINC write *inside* the valid-zSp
block (after the `if (fabs(dr) < ...)` block closes, before the zSp block closes). `psi` is
always valid there. The `validData == FALSE` cleanup block was simplified to just set
`vxTmp = -LARGEINT` and `fScale = 0.0`.

**Effect:** VZINC mode now writes the correct incidence angle for all valid-elevation pixels
(whether or not offset data is good), and writes nothing for invalid-elevation pixels (those
already get `vxTmp = -LARGEINT` from the cleanup block).

**To revert:** Restore the two original `if (outputImage->vzFlag == VZINC)` blocks outside
the valid-zSp block and remove the one inside it.

## readXYDEM.c  — readXYCropVel()

**Problem:** Two consecutive `replace_wildcard` pairs assigned to the same variables:
```c
vxFile = replace_wildcard(velFile, "*", "vx");  // result immediately overwritten — leaked
vyFile = replace_wildcard(velFile, "*", "vy");  // result immediately overwritten — leaked
vxFile = replace_wildcard(velFile, "vv", "vx");
vyFile = replace_wildcard(velFile, "vv", "vy");
```
The first pair allocated strings that were leaked when overwritten. If `velFile` contains `*`
but not `vv` the second call returns NULL or the original, so the `vv` convention silently
fails while appearing to work.

**Fix:** Removed the first two lines (the `*` wildcard pair). Only the `vv` pair remains.
Files using the older `*` wildcard convention will now fall through to the multi-band
fallback path (opens the file directly and looks for bands labelled "vx"/"vy").

**To revert:** Restore the two `replace_wildcard(velFile, "*", ...)` lines before the `vv` pair.

## readOffsets.c — readOffsetParams()

**Problem:** `int32_t lineCount, eod;` — `lineCount` uninitialised. Immediately passed to
`getDataString(fp, lineCount, ...)` which uses it as an incrementing line counter. All other
callers in this file initialise `lineCount = 0`. No runtime crash (return value is reassigned)
but error messages would print a garbage line number.

**Fix:** Changed declaration to `int32_t lineCount = 0, eod;`.

**To revert:** Remove the `= 0` initialiser.

## make3DMosaic.c

Four independent fixes:

### 1. Outer loop condition
**Problem:** `for (aPhaseImage = allImages; aPhaseImage->next != NULL; ...)` skips the last
image as the ascending (outer) partner. It still appears as a descending (inner) partner, but
if it happened to be the correct ascending image for a given pair, that pair is silently skipped.

**Fix:** Changed condition to `aPhaseImage != NULL`. With this change, when `aPhaseImage` is
the last image its inner loop (`dPhaseImage = aPhaseImage->next`) starts from NULL and exits
immediately, which is correct.

**To revert:** Change `aPhaseImage != NULL` back to `aPhaseImage->next != NULL`.

### 2. strncpy filename overwrite
**Problem:** `strncpy(dPhaseImage->file, "nophase", 7); dPhaseImage->file[7] = '\0';`
overwrites the beginning of the original filename buffer in-place. `file` is a `char *`
pointing into the input file's loaded data; this modifies shared memory. The intent is to
permanently flag the image as having no overlap for future loop iterations.

**Fix:** Replaced with `dPhaseImage->file = strdup("nophase");` which reassigns the pointer
to a new allocation rather than corrupting the original buffer.

**To revert:** Restore the `strncpy` / `[7]='\0'` pair.

### 3. Data race on `->used` flag
**Problem:** `aPhaseImage->used = TRUE` and `dPhaseImage->used = TRUE` were written inside
`#pragma omp for` without synchronisation. `aPhaseImage` and `dPhaseImage` are shared across
all threads. On x86_64 the race is benign (all threads write the same value to the same
aligned int32_t), but it is formally undefined behaviour.

**Fix:** Added `#pragma omp atomic write` before each assignment.

**To revert:** Remove the two `#pragma omp atomic write` directives.

### 4. Dead `Aset` variable
**Problem:** `int32_t validData, Aset;` — `Aset` was set to `FALSE` each iteration and never
read. Remnant of a removed optimisation.

**Fix:** Removed `Aset` from the declaration and deleted the `Aset = FALSE;` assignment.

**To revert:** Re-add `int32_t validData, Aset;` and `Aset = FALSE;`.

## parseInputFile.c — parseStateVectorsGeojson()

**Problem:** Function declared `static int32_t` but fell off the end without a `return`
statement. Return value is not used by the caller so no runtime effect, but technically
undefined behaviour and generates a compiler warning with `-Wall`.

**Fix:** Added `return 0;` before the closing `}`.

**To revert:** Remove the `return 0;`.

## initRoutines.c

Two independent fixes:

### 1. computeVxy() — detC guard ordering
**Problem:** The matrix inverse was computed (`Cinv[i][j] = .../detC`) before the
`if (detC < 0.25)` guard was checked. For `detC == 0` this produces `Inf` elements (IEEE 754
does not trap), which are then discarded when the guard fires. Conceptually wrong and could
interact badly on non-IEEE hardware or future code changes.

**Fix:** Moved the `if (detC < 0.25) { ...; return; }` block to immediately after computing
`detC`, before computing `Cinv`. The inverse is now only computed when `detC` is large enough.

**To revert:** Move the `if (detC < 0.25)` block back to after the `*scaleY = 1.0 / ey;` line
and change `return;` inside it back to not returning (the original pattern ended the function
there anyway).

### 2. getIntersectOld() — dead code after return
**Problem:** A `return;` on line 705 was followed by a dead `if (inA == FALSE && inD == FALSE)`
block that could never execute.

**Fix:** Removed the dead block (left the `return;` in place).

**To revert:** Restore the `if (inA == FALSE && inD == FALSE) { ... }` block after `return;`.

## scalingFunctions.c — redoNormalization()

**Problem:** `scaleZ[i][j] += sqrt(syTmp[i][j] * sxTmp[i][j]) * ...` — `sqrt` of a negative
value produces NaN silently (IEEE 754). `sxTmp`/`syTmp` are inverse-error-squared weights and
should always be positive, but there is no guard against sentinel values leaking through.

**Fix:** Added `if (syTmp[i][j] > 0.0f && sxTmp[i][j] > 0.0f)` before the `sqrt` call.

**To revert:** Remove the surrounding `if` and dedent the `scaleZ` line.

## mosaic3d.c

Two independent fixes:

### 1. logInputs3d() — fixed 1024-byte log path buffer
**Problem:** `logFile = (char *)malloc(1024)` — if `outFileBase` exceeds ~1018 characters the
subsequent `strcat` overflows silently.

**Fix:** Changed to `malloc(strlen(outFileBase) + 16)`.

**To revert:** Change back to `malloc(1024)`.

### 2. readReferenceVelMosaic() — NULL checks after pointer use
**Problem:** Eight NULL checks on `vxFile`, `vyFile`, `exFile`, `eyFile` (filename strings)
and on file-handle `fp` appeared either before the file was opened (checking a malloc'd
filename that can never be NULL without a crash elsewhere) or after `fseek(fp, ...)` had
already dereferenced `fp`. The pre-open filename checks are dead code; the post-fseek `fp`
checks are both dead and too late.

**Fix:** Removed all eight dead NULL checks. `openInputFile` already calls `error()` and exits
if the file cannot be opened, so `fp` is never NULL after a successful call.

**To revert:** Restore the four `if (xFile == NULL) error(...)` checks before `openInputFile`
and the four `if (fp == NULL) error(...)` checks after `fseek`.
